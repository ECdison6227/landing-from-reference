# 按需交付与部署

只有用户要求相应交付形态时才执行本节。用户只要本地预览时，不默认部署、上传代码或制作整套后端。

## 独立 HTML

检查项目自身的单文件导出能力或适用的构建插件，再决定打包方式。常见方法是将样式、脚本、字体和小素材内联。具体参数依据当前构建工具版本，不照抄另一个项目的配置。

注意动态 import、worker、WebGL 纹理、字体、图片和媒体是否仍引用路径。避免把与展示无关的模型或编辑器整套依赖打入页面。直接用 `file://` 打开产物，观察失败请求并测试交互；需要离线时再断网验证。

交付说明区分“单文件”与“完全离线”。远程照片、表单 API 或产品链接仍可能需要联网。

## 报名

静态页面本身不能提供可靠的持久化数据库。按用户要求选择已有服务、托管表单或小型 API；不为了纯介绍页自行部署产品后端。

最小实现包含邮箱有效性检查、参数化写入、重复申请策略、提交中的状态、失败重试和行内成功提示。需要 SQLite 时可采用 `email`、首次申请时间、最近申请时间、申请次数等字段；遵守现有数据结构，不覆盖线上表。

独立展示页不应因报名而建立产品会话或跳转产品。若复用已有接口，检查接口副作用和 cookie；仅在前端设置 `credentials: "omit"` 不能证明后端没有创建会话。

## 已授权的服务器发布

1. 读取目标域名、子路径、Web 服务器配置、当前文件版本和相关服务，确认发布范围。
2. 保存待替换文件和配置的备份，记录回退位置；不覆盖无关站点、服务或数据库。
3. 配置子路径时一并核对资源、API、锚点和跳转目标。Nginx 配置先检查再 reload；失败时恢复本次配置。
4. 覆盖前重新核对线上文件的时间或哈希。发现别的会话刚发布时，先对比和协调，不直接覆盖。
5. 线上用真实浏览器复测页面与必要的相邻路由；确认测试表单数据落库，并清理仅由本次测试创建的记录。

二维码可单独部署，便于过期后换图；既有打包方式不同则沿用其发布机制。报告失效时间应来自用户或原图，不凭空推算。

不要把服务器密码、SSH 密钥、真实报名数据或群码自动放进公开仓库。优先使用已有 SSH 配置或凭据管理方式。
