# 实现与验收

## 真实组件与性能

示例数据通过产品已有 schema 或类型约束。使用真实卡片和播放器时，确认所需 context、尺寸、媒体 URL 和全局快捷键，避免直接连接用户的数据 store。

昂贵的 WebGL 背景不必在每张轮播缩略图中同时运行。采用静态内容缩略图、可见区域动态展示、延迟加载或暂停不可见演示；离开页面时释放计时器和事件监听。减少动态效果时，保留可理解的静态内容和手动控件。

## 页面与入口

| 形态 | 主要动作 | 返回与数据 |
| --- | --- | --- |
| 产品内首页 | 开始使用进入实际用户界面；示例入口应说明其行为 | 保留当前内容，提供可发现的返回首页按钮 |
| 独立展示页 | 展示、联系或报名；未开放的入口真正禁用 | 不自动进入产品，不保留无关的登录态 |
| 独立 HTML | 依据约定决定按钮目的地 | `file://` 下也要验证，外链应明确依赖网络 |

覆盖编辑器的 Landing 应阻止底层播放器响应方向键和滚轮。退出全屏、关闭编辑抽屉、暂停媒体后返回首页，避免页面继续播放声音。再次进入时，不重建用户项目。

已有首次访问标记时，同时检查“直接进入”“看示例”“返回”“刷新”“再次进入”。不要仅把某个端口换成另一个就认定入口正确；实际检查目的页身份。

## 文案与视觉

主张写用户能获得的结果，功能数字来自实际代码。不要把所有技术实现细节放进宣传文案。可保留少量英文标签增强层级，中文标题要留意单字换行和移动端长度。

参考站提供灵感，产品本身提供语义和品牌依据。用户明确要求全新 UI 时，不沿用旧页的视觉结构；需要接入原产品的流程时，保留其行为契约。

## 浏览器验收

- 桌面与手机检查内容顺序、横向溢出、按钮遮挡、二维码留白和字体加载。
- 自动轮播之外，实际测试拖动、点击、方向键、暂停及减少动态效果。
- 产品入口和返回路径测试内容保留；独立展示页测试入口确实不可点击。
- 有表单时测试成功、失败、重复提交与不跳转的要求；使用专门测试数据并清理自己新增的记录。
- 运行必要的类型检查、生产构建和有意义的回归测试，记录已知的外链与运行环境限制。

测试使用独立 context 或临时浏览器配置，不读取用户真实项目或改变其浏览器数据。
