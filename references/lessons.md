# 实际工作中值得保留的经验

- **入口要验证页面身份。** 本机多个目录可能各有开发服务；HTTP 200 不能证明是本次代码。核对进程工作目录、页面内容和路由，再填写链接。产品首页不应误入旧设置页。
- **返回路径属于完整流程。** 首次进入的记忆标记不能取代导航；从示例或编辑器回到介绍页时，保留用户内容，避免只能清理浏览器存储才能返回。
- **展示与体验在开工时区分。** 公开展示、报名、登录、审核和实际产品是不同能力，依据本次要求连接，不能把上次的服务器流程整套带过来。
- **工具依赖放在明确目录。** 在没有自己 `package.json` 的文件夹运行 `npm install`，可能修改上级产品仓库。配套工具使用本技能仓库或独立虚拟环境。
- **Windows 的可执行文件有差异。** `spawn('npx', …)` 可能找不到 `npx.cmd`；能使用本地 Node 入口时，直接通过 `process.execPath` 启动。不要为了运行一个工具改写系统 PATH。
- **Git Bash 可能改写路径。** `/site/api/...` 一类构建变量可能变成 Windows 文件路径。使用 PowerShell 或关闭相应转换后核对产物中的真实值。
- **UTF-8 要贯穿写入与管道。** Windows PowerShell 向外部程序传递中文时可能使用不同编码；文件使用明确的 UTF-8 读写，修改后检查实际中文，而不只检查能否编译。
- **不要与其他会话互相覆盖。** 本地查看未提交改动，必要时使用独立工作树；发布前比对线上版本。只改用户授权的那份页面。
- **二维码必须实测。** 裁切、二值化或缩放都可能破坏编码。比较解码内容，保留白边；真实群链接会过期，不把“能解码”写成“永远有效”。
- **参考站不等于产品设计规范。** 相同的段落和动效可以用于不同品牌；不要每次都复制白底、衬线字或特定数量的卡片。
